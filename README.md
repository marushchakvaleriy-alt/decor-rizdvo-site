# decor_rizdvo — сайт-вітрина

Готовий сайт для Instagram-магазину новорічного декору **decor_rizdvo**.

Сайт багатосторінковий, з анімаціями (легкий сніжок, плавна поява блоків при прокрутці, анімовані елементи в hero-блоці):

- **index.html** — головна: hero-блок, короткий каталог, переваги, коротко "про нас"
- **catalog.html** — повний каталог (ялинки, вінки, гірлянди та прикраси) з описами
- **masterclass.html** — окрема сторінка про майстер-клас (кроки, для кого, вартість)
- **about.html** — історія бренду, цінності, як проходить робота
- **contact.html** — контакти, форма заявки, часті запитання (FAQ)
- **admin.html** — захищена входом адмін-панель, показує всі заявки клієнтів

Заявки з форми зберігаються в базі даних **Firebase (Firestore)**.

Сайт повністю готовий — не потрібно нічого програмувати.

## Крок 6. Автоматичний деплой на GitHub Pages (рекомендовано)

Це найзручніший спосіб: один раз налаштовуєте, а далі — просто подвійний клік по файлу, коли хочете оновити сайт.

### Що потрібно встановити (один раз, якщо ще не встановлено)

1. **Git** — https://git-scm.com/download/win (встановити з налаштуваннями за замовчуванням)
2. **Node.js** — https://nodejs.org (кнопка **LTS**, встановити з налаштуваннями за замовчуванням)

Перевірити, чи все встановилось: відкрийте командний рядок (`cmd`) і введіть `git --version` та `node --version` — мають з'явитись номери версій.

### Одноразове налаштування

1. Розпакуйте проєкт `decor_rizdvo_site` у зручне місце на комп'ютері (наприклад, `Документи\decor_rizdvo_site`).
2. Двічі клацніть на файл **`setup.bat`**.
3. Дочекайтесь, поки все встановиться (з'явиться повідомлення «Готово!») → натисніть будь-яку клавішу, щоб закрити вікно.

Це:
- підключає вашу папку до репозиторію `decor-rizdvo-site` на GitHub;
- встановлює невеликий інструмент `gh-pages`, який публікує сайт.

### Щоразу, коли хочете опублікувати зміни

1. Відредагуйте потрібні файли всередині папки **`public`** (текст, ціни, фото тощо).
2. Двічі клацніть на файл **`deploy.bat`**.
3. Дочекайтесь напису «Deployment completed successfully!».
4. Через 1–2 хвилини оновлений сайт буде доступний за адресою:
   **https://marushchakvaleriy-alt.github.io/decor-rizdvo-site/**

Більше нічого робити не потрібно — жодного ручного завантаження файлів у браузер.

### Увімкнути GitHub Pages (лише один раз, після першого запуску `deploy.bat`)

1. Зайдіть у репозиторій **decor-rizdvo-site** на github.com → вкладка **Settings**.
2. У лівому меню — **Pages**.
3. У розділі **Build and deployment → Source** виберіть **«Deploy from a branch»**.
4. У розділі **Branch** виберіть гілку **`gh-pages`** і папку **`/ (root)`** → **Save**.
   (Гілка `gh-pages` з'явиться в списку тільки ПІСЛЯ того, як ви хоч раз запустили `deploy.bat`.)
5. Через 1–2 хвилини вгорі з'явиться посилання на ваш сайт.

## Альтернатива: завантаження вручну через браузер (без Git/Node.js)

Якщо не хочете нічого встановлювати — можна й надалі оновлювати сайт вручну:

1. Зайдіть у репозиторій на github.com → **Add file → Upload files** (якщо репозиторій порожній — натисніть посилання **"uploading an existing file"**).
2. Перетягніть туди **весь вміст** папки **`public`** (усі `.html`-файли, папки `css`, `js`, `img`).
3. **Commit changes**. Файли, які вже існували в репозиторії, автоматично оновляться, а нові додадуться.
4. У Settings → Pages виберіть гілку **`main`**, папку **`/ (root)`**.

⚠️ Щоразу, коли я оновлюю сайт (додаю сторінки, змінюю дизайн тощо), повторюйте ці ж 4 кроки з новою версією папки `public` — просто перетягніть все її вміст ще раз і зробіть Commit changes.

⚠️ Не змішуйте обидва способи для однієї гілки одночасно — оберіть один: або `deploy.bat` (гілка `gh-pages`), або ручне завантаження (гілка `main`). Простіше й надійніше — `deploy.bat`.

## Типові проблеми

**deploy.bat видає помилку "npm not recognized" або "git not recognized"**
→ Node.js або Git не встановлені (або комп'ютер не перезапускався після встановлення). Встановіть їх і перезапустіть комп'ютер.

**deploy.bat пише помилку про доступ / авторизацію (403 / Permission denied)**
→ Git просить увійти в GitHub. При першому пуші зазвичай відкриється вікно браузера — увійдіть у свій акаунт GitHub і дозвольте доступ.

**Форма не надсилається / нічого не відбувається**
→ Перевірте `public/js/firebase-config.js` — там мають бути реальні дані, а не заглушки.

**В адмінці нічого не показує, помилка "permission denied"**
→ Перевірте правила Firestore (Firebase → Firestore Database → Rules) — мають бути опубліковані правила з файлу `firestore.rules`.

**Не вдається увійти в admin.html**
→ Перевірте email/пароль, або створіть користувача заново: Firebase → Authentication → Users → Add user.

**Сайт показує помилку 404**
→ Перевірте, що в Settings → Pages вибрана правильна гілка (`gh-pages`, якщо користуєтесь `deploy.bat`, або `main`, якщо завантажували вручну) і що там дійсно є файл `index.html`.

## Довідка: Firebase з нуля (якщо колись знадобиться повторити)

<details>
<summary>Натисніть, щоб розгорнути</summary>

1. **console.firebase.google.com** → Add project → вимкнути Google Analytics → Create project.
2. **Build → Firestore Database → Create database** → регіон Europe (`eur3`) → Start in test mode.
3. **Build → Authentication → Get started → Email/Password → Enable → Save** → вкладка Users → Add user (email + пароль для входу в адмінку).
4. **Settings (шестерня) → Project settings → Your apps → `</>` Web** → зареєструвати застосунок → скопіювати `firebaseConfig` → вставити у `public/js/firebase-config.js`.
5. **Firestore Database → Rules** → вставити вміст `firestore.rules` → Publish.

</details>
